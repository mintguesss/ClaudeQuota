# ClaudeQuota

桌面上隨時看得到 Claude 訂閱額度用了多少。

```
┌─────────────────────────────────────────┐
│  ✳ Claude              ⚡  ↻  ─  ✕      │
│                                         │
│  5 小時額度                        50%  │
│  ▬▬▬▬▬▬▬▬▬▬▬▬▬▭▭▭▭▭▭▭▭▭▭▭▭▭▭            │
│  剩 4 小時 37 分 · 00:50 重置           │
│                                         │
│  每週額度                          15%  │
│  ▬▬▬▬▬▭▭▭▭▭▭▭▭▭▭▭▭▭▭▭▭▭▭▭▭▭▭▭            │
│                                         │
│  即時官方數字                            │
└─────────────────────────────────────────┘
```

- **只顯示官方數字**——拿不到就明講拿不到，不做任何用量推估
- 系統列常駐圖示，卡片可縮成一條細橫條，兩者都能拖到你要的位置
- 純 Python + tkinter，沒有瀏覽器、沒有 Electron，記憶體約 60 MB

## 需要什麼

| 項目 | 說明 |
|------|------|
| Windows 10／11 | 用到 Segoe Fluent Icons、系統列 API、DPI 感知 |
| Python 3.9+ | |
| `pystray`、`pillow` | `pip install pystray pillow` |
| Claude Code 已登入 | 主要資料來源要用它存在本機的 OAuth token |
| Claude 桌面版（選用） | 後備資料來源；沒裝也能用 |

## 啟動

雙擊 **`啟動.vbs`**——它用 `pythonw` 執行，不會跳出黑色命令列視窗。

> `啟動.vbs` 必須維持 **ASCII 純文字**。WScript 是用 ANSI 解析 `.vbs` 的，
> 在裡面寫 UTF-8 中文註解會讓整個腳本解析失敗，而且**不會有任何錯誤訊息**，
> 只是靜靜地什麼都沒發生。

### 開機自動啟動

1. `Win + R` → 輸入 `shell:startup` → Enter
2. 把 `啟動.vbs` 的**捷徑**放進開啟的資料夾

## 怎麼用

### 三種顯示狀態

同一個東西的三種形態，同時只會有一個看得見：

```
卡片  ──[ ─ ]──▶  橫條  ──[ 點一下 ]──▶  卡片
  │                 │
  └──[ ✕ ]──┬───────┘
            ▼
          全部收起（點系統列圖示叫回來）
```

橫條是卡片縮小後的樣子：

```
✳  5h  50% ▬▬▬▭▭▭   │   週  15% ▬▭▭▭▭▭
```

卡片與橫條**共用同一組位置**，伸縮時左上角不動，看起來就是同一個視窗在變形。
位置記在 `widget_state.json`，下次啟動回到原處。

### 卡片按鈕

滑鼠移上去，卡片底部那行字會說明用途。

| 按鈕 | 用途 |
|------|------|
| ⚡ | 讓 5 小時視窗從現在起算（見下方） |
| ↻ | 立即重讀。**受端點限流**，還沒到可以再問的時間就只重讀本機並告訴你還要等幾秒——硬打只會吃 429，越按越慢 |
| ─ | 縮成橫條 |
| ✕ | 全部收起——**只是收起來，程式還在系統列裡跑** |

收起來之後**左鍵點系統列圖示**就能叫回來。真的要結束程式請用系統列右鍵選單的
「結束 ClaudeQuota」。

### 系統列

- **左鍵**：顯示／隱藏
- **右鍵**：重新整理、開啟 5 小時視窗、切換圖示樣式、移回畫面內、結束

圖示樣式有兩種，選擇會記住：

| 樣式 | 說明 |
|------|------|
| `burst` | 狀態色圓角底 + 白色星芒（預設）。一眼認得出是 Claude |
| `number` | 狀態色底 + 白色大數字 + 底部進度細條。看得到確切數字 |

> **圖示大小改不了。** 通知區的格子是 Shell 定死的正方形——
> `GetSystemMetrics(SM_CXSMICON)`，在 175% 縮放下是 28×28。沒有 per-app 的 API
> 可以放大，寬圖也只會被壓扁塞進去；舊版能改整條工作列的 `TaskbarSi` 登錄檔，
> 微軟在 Windows 11 22H2 之後移除了。
>
> 唯一能爭取的是讓內容塞滿那 28px。實測把字寬上限從 78% 調到 96%，
> 數字在 28px 上的實際高度從 14px 變 16px——就這樣，沒有別的辦法。

程式啟動幾秒後會把系統列圖示設成「一律顯示」（登錄檔
`HKCU\Control Panel\NotifyIconSettings` 的 `IsPromoted`），免得被收進工作列的
`^` 溢位選單裡找不到。

## 資料從哪來

**只認官方數字**，兩個來源、優先順序如下：

| 來源 | 延遲 | 需要 |
|------|------|------|
| **官方用量端點**（主要） | 約 2 分鐘（端點限流） | Claude Code 已登入 |
| **桌面版本機快取**（後備） | 最多 5 分鐘 | Claude 桌面版有在跑 |

兩個都拿不到就在卡片上直接寫「讀不到額度資料」。**不做任何用量推估**——
寧可沒有數字，也不要給一個看起來像真的的假數字。

卡片頁尾隨時標明現在用的是哪一種。

### 主要來源

Claude Code 登入後會把該帳號的 OAuth token 存在本機。程式讀它，去問 Anthropic
自己的用量查詢端點，拿到即時的兩個視窗用量與各自的 `resets_at`。

端點與標頭定義在 [`quota_source.py`](quota_source.py) 最上方的常數，要改在那裡改。

這樣做解掉兩個問題：

1. **延遲從 5 分鐘降到約 2 分鐘**——桌面版快取是每 5 分鐘寫一次檔，
   燒得快的時候那 5 分鐘很致命
2. **重置時間是伺服器給的精確值**——不必從歷史回推，也不用標「約」

而且桌面版沒開也能用。

實作上的分寸：

- 全程**唯讀**，只查自己的帳號，不會產生任何額度用量
- 網路呼叫一律跑在**背景執行緒**，不能擋住 tkinter 主執行緒
- token 快過期（留 60 秒緩衝）就當作沒有，**不自己做 refresh**——
  那是 Claude Code 的事，硬搶著換可能把它的登入狀態弄壞

#### 更新節奏會自己收斂

這個端點**有速率限制，而且沒有文件**。實測以 20 秒間隔連打 12 次：

```
21:02:01  200  ← 成功
21:02:21  429
21:02:41  429
21:03:01  429
21:03:21  429
21:03:41  429
21:04:02  200  ← 成功（距上次 121 秒）
```

看起來大約是「每 2 分鐘 1 次」，但 429 回的 `Retry-After` 是 `0`（等於沒給），
也沒有任何 `RateLimit-*` 標頭，所以沒有保證，Anthropic 隨時可能調整。

**打得比限制快不會更即時**——只會拿到一串 429，然後整段時間退回 5 分鐘的桌面版快取，
反而比乖乖等更舊。

所以不寫死猜測值，改成自己收斂：

| 事件 | 動作 |
|------|------|
| 成功 | 間隔 × 0.9（下限 120 秒）——慢慢逼近端點容許的最快節奏 |
| 429 | 間隔 × 1.5（上限 600 秒），並等這麼久再試 |
| 401／403 | 靜音 15 分鐘 |
| 其他 HTTP 錯誤 | 靜音 5 分鐘 |

起始 150 秒。連續成功會一路收斂到 120 秒的下限；撞牆就自動退開，
不需要我猜對限制是多少。無論額度多滿都用同一套節奏，**永遠盡可能即時**。

靜音期間自動走桌面版快取，**卡片頁尾會寫明原因與還要等多久**，不會默默地就變舊。
`python quota_source.py` 也會印出目前的間隔與 API 狀態。

### 後備來源

Claude 桌面版會把伺服器回傳的額度快取成 `plan-usage-history.json`，每 5 分鐘一筆：

```json
{"version": 2, "samples": [{"t": 1785676994026, "u": {"fh": 51, "sd": 43}}]}
```

`fh` = 5 小時額度已用 %，`sd` = 每週額度已用 %。

Windows 從 Microsoft Store 安裝的是 MSIX 封裝，檔案在
`%LOCALAPPDATA%\Packages\Claude_*\LocalCache\Roaming\Claude\`，
**不是**一般的 `%APPDATA%\Claude`。程式用關鍵字搜尋 + 容錯解析，換版本也還找得到。

這條路沒有 `resets_at`，得自己回推視窗起點：

1. 快取歷史裡 `fh` 驟降（例：`100 → 0`）那一刻就是新視窗的起點
2. 桌面版沒開的期間會有斷層、錯過重置。這時改用 Claude Code 對話紀錄的時間戳
   走一遍視窗邊界

兩種都只能給**上限**（真正開啟視窗的可能是網頁或手機版，本機看不到），
所以取兩者較早的，並在時間前面標「約」。

> 曾經以為視窗起點一律對齊 10 分鐘邊界，拿它去修正還真的把誤差壓到 0。
> 後來接上官方端點才發現 `resets_at` **不一定**在邊界上（實測有 `00:49`）——
> 那條規律只是幾次巧合。能拿到真值就別用回推。

## ⚡ 開啟 5 小時視窗

5 小時視窗是**第一次用量才開始計時**的，所以「還沒開始用」時根本沒有視窗在跑。

卡片上的 ⚡（或系統列選單的「開啟 5 小時視窗」）會執行一次最小呼叫
`claude -p "hi"`，把視窗從現在點著。用 CLI 是因為它走的是**訂閱額度**；
直接打 Anthropic API 是另一套計費，不會影響訂閱視窗。

### 自動起算

系統列選單的「**重置後自動起算**」（預設開）會在偵測到沒有進行中的視窗時自動打一次。
判斷依據是拿不到 `resets_at`。

冷卻時間 `AUTO_POKE_COOLDOWN_MIN = 12` 分鐘。走官方端點時其實不必這麼長，
但退回桌面版快取時**必須大於它 5 分鐘的取樣間隔**——否則打完之後快取還沒反映，
會被判定成「還是沒視窗」而重複觸發。

> **取捨**：視窗一開就開始倒數 5 小時。沒在工作時把它點著，等於白白燒掉一段——
> 真正開始做事時可能只剩不到 1 小時。想要「每次都拿到完整 5 小時」就把這項關掉，
> 改用手動 ⚡。
>
> 另外這只在程式跑著的時候有效。電腦關機或睡眠時沒人去打那一下，
> 實際行為是「下次開機才起算」。

## 更新頻率與成本

`REFRESH_SEC = 10` 秒。實測整支程式 60 秒只用掉 **0.031 秒 CPU 時間**
（單核 0.05%、22 核機器 0.002%），記憶體約 60 MB。之所以這麼便宜：

- 桌面版資料夾的遞迴掃描要 ~44ms（裡面有好幾 GB 的 VM bundle），清單快取 5 分鐘
- JSON 解析用 `(mtime, size)` 當鍵快取，檔案沒變就不重解析 → 熱路徑 **0.047ms**
- 卡片重繪要 ~34ms，只在畫面內容真的變了才做（`_signature()` 比對）
- 網路照自己收斂出來的節奏（120～600 秒），不隨畫面更新

## 實作筆記

踩過的坑，照順序寫在這裡免得重蹈覆轍。

### 畫面糊掉 → DPI 感知

不宣告 DPI 感知的話，Windows 會把整個視窗**點陣拉伸**（本機 175% 縮放），
再怎麼細畫都是糊的。`enable_dpi_awareness()` 必須在建立 tkinter 視窗**之前**呼叫；
之後 tkinter 座標就是實體像素，卡片也照倍率放大來畫。

### 邊緣鋸齒 → 不要用 tkinter Canvas 畫圖

tkinter 的 Canvas 沒有反鋸齒，圓角、圖標、線條邊緣全是階梯。
改用 Pillow 以 3 倍超取樣繪製、LANCZOS 降採樣，再貼成 `ImageTk.PhotoImage`。

### 圓角與透明

圓角是用色鍵（`-transparentcolor`）裁的，所以遮罩的 alpha 要**二值化**——
半透明的邊緣像素若跟色鍵混色會出現黑邊。透明感則是整窗 `-alpha 0.95`。

### 中文變豆腐格 → Pillow 不做字型 fallback

Segoe UI 沒有中文 glyph，Pillow 又不會自動換字型，只會畫成方塊。
中文一律指定微軟正黑體。✕ / ↻ / ⚡ 則走 Segoe Fluent Icons（`SegoeIcons.ttf`）
的私用區碼位——注意微軟正黑體 Light 連 `✓` 都沒有，訊息文字別混用符號。

### pystray 選單沒反應 → 它用 `co_argcount` 決定怎麼呼叫

```python
argcount = action.__code__.co_argcount
if argcount == 0:
    def wrapper0(*args): return action()   # 零參數 → 包起來忽略引數
    return wrapper0
return action                              # 否則直接餵 (icon, item)
```

寫成 `lambda _i=None, k=key: ...` 的話 `co_argcount` 是 2，pystray 會把
`(icon, item)` 直接餵進來，**`k` 被第二個引數蓋成 MenuItem 物件**。
選單動作一定要用真正的零參數閉包。

### 狀態檔整包失憶 → BOM

`widget_state.json` 若被帶 BOM 的編輯器（或 PowerShell 的 `Out-File -Encoding utf8`）
寫過，用 `encoding="utf-8"` 讀會直接拋 `JSONDecodeError`，設定就靜靜歸零。
讀取一律用 `utf-8-sig`。

### Claude 標誌

`claude_logo.png` 是 Anthropic 的商標圖形，從已安裝的桌面版 MSIX 套件裡取得的
官方 app icon，**沒有跟著版本控制一起散布**。程式在缺檔時會自己去
`%ProgramFiles%\WindowsApps\Claude_*\assets\` 複製一份；連桌面版都沒裝就退回
程式內建的手繪星芒（比較醜，但至少畫得出來）。

系統列的星芒形狀是從那張圖取「亮部 ∩ 不透明」當遮罩挖出來的，不是重畫的。

| 檔案 | 用途 |

## 資料與隱私

**讀取的本機檔案**

| 路徑 | 讀什麼 |
|------|--------|
| `~/.claude/.credentials.json` | Claude Code 的 OAuth token，只用來向官方端點驗證身分 |
| `%LOCALAPPDATA%\Packages\Claude_*\...\plan-usage-history.json` | 桌面版存的額度快取（後備來源） |
| `~/.claude/projects/*.jsonl` | **只讀時間戳**，用來在後備模式下回推視窗起點。不讀對話內容 |

**對外連線只有一個**：帶著你自己的 token 去問 Anthropic 官方的用量端點。
除此之外不連任何地方——沒有遙測、沒有分析、沒有第三方伺服器。

**不會做的事**：不上傳帳號、對話、token 或用量資料；不寫入任何 Claude 的檔案；
不做用量推估。額度資料全部來自官方，拿不到就明說拿不到。

唯一會寫的檔案是本資料夾裡的 `widget_state.json`（視窗位置與偏好），
以及登錄檔 `HKCU\Control Panel\NotifyIconSettings` 的 `IsPromoted`
（讓系統列圖示不要被藏進溢位選單）。

## 疑難排解

**先跑這個**，它會印出目前讀到什麼、以及兩個來源各自的狀態：

```bash
python quota_source.py
```

| 症狀 | 可能原因 |
|------|----------|
| 雙擊 `啟動.vbs` 完全沒反應 | 檔案被存成 UTF-8 了。必須是 ASCII 純文字 |
| 卡片顯示「讀不到額度資料」 | Claude Code 沒登入或 token 過期，且桌面版也沒在跑 |
| 數字比官網舊 | 退回桌面版快取了，最多落後 5 分鐘。頁尾會寫明原因（多半是端點速率限制） |
| 系統列圖示找不到 | 被收進工作列的 `^` 裡了。從那裡拖到工作列上即可常駐 |
| 卡片跑到畫面外 | 系統列右鍵 →「移回畫面內」 |
